## 🚫 Что НЕ делать (категорически)

### Безопасность и данные
1. **НЕ возвращать mock-fallback при ошибке логина** — пользователь должен видеть честную ошибку, а не получать доступ через mock-юзеров
2. **НЕ делать `requireRole('director')` эквивалентным `admin`** — это разные роли, директор НЕ должен иметь admin-API
3. **НЕ читать `managerRegions` из query-параметра клиента** — клиент подменит и увидит чужие регионы. Брать только из БД по `userId` из JWT
4. **НЕ хранить пароль в коде или истории git** — только `.env`, `.pgpass`, `/root/.pgpass.analizator`
5. **НЕ светить пароль БД в `console.log`** — даже email сброса пароля логировать не надо
6. **НЕ глотать ошибки `catch {}`** — минимум `console.error(err)`, иначе диагностика невозможна
7. **НЕ выдавать JWT без `jti`** — без него blacklist не работает
8. **НЕ забывать `userId` фильтр в SQL** — без него пользователь увидит чужие данные

### Архитектура и данные
9. **НЕ создавать новые источники данных вне `SharedDataProvider`** — единый источник для всех панелей. Если нужны новые данные — добавить в provider и связать с `mdlp-data-updated` событием
10. **НЕ вызывать `setMdlpData` напрямую с захардкоженными mock'ами** — только через `reloadFromServer()` из БД
11. **НЕ хардкодить продажи** в JSX (`<div>463 млн</div>`) — только из props/state, которые в итоге идут из БД
12. **НЕ держать одинаковые компоненты в двух местах** — если видишь две панели/два списка/два дашборда, один из них надо удалить
13. **НЕ полагаться на одинаковые имена полей между Figma-mock и API** — типы из Figma могут отличаться (`fullName` vs `name`)

### Frontend
14. **НЕ адаптировать код из Figma при первом импорте** — брать один в один, создавать недостающие зависимости. Адаптация — потом отдельной задачей
15. **НЕ использовать `jspdf` для кириллицы** — там сломанные шрифты. Использовать браузерную печать через `Blob + URL.createObjectURL + window.open`
16. **НЕ добавлять тёмную тему** — проект только светлый, удаление dark классов уже выполнено
17. **НЕ использовать `any` без крайней необходимости** — типизировать API-ответы
18. **НЕ использовать `key={i}` (индекс массива)** в `.map()` для списков с возможным reorder/delete — ломает state инпутов. Использовать стабильный `key={item.id}`

### Деплой и инфраструктура
19. **НЕ использовать `localhost` в nginx `proxy_pass`** — резолвится в IPv6 `[::1]`, а Node слушает только IPv4. Использовать `127.0.0.1:5000`
20. **НЕ забывать URL-encode пароль БД** в `DATABASE_URL` — спецсимволы (`<`, `>`, `$`, `+`, `#`, `@`) ломают парсер
21. **НЕ делать `git push` или `pm2 restart` без явной просьбы пользователя** — он сам контролирует когда обновлять прод
22. **НЕ оставлять `console.log` с production-данными** — Vite в prod-сборке убирает (`drop_console`), но в server/ остаются
23. **НЕ запускать background-агентов для Figma MCP** — у них нет доступа к Figma. Только основной контекст

### Подход к работе
24. **НЕ амендить коммиты** — создавать новые. Stop-hook автокоммитит, амендить можно только до push'а
25. **НЕ откатывать коммиты без подтверждения** — `git reset --hard`, `force push` — только по явной просьбе
26. **НЕ удалять файлы оптом** — сначала проверить grep'ом что нет импортов из удаляемого файла
27. **НЕ запускать `npm install` с `--force`** — без явной необходимости, ломает peerDependencies
28. **НЕ ставить новые npm-пакеты без согласования** — проверять что нужное не уже установлено (`grep package.json`)
29. **НЕ заходить в личный кабинет пользователя через браузер** — у меня нет доступа к GUI; для UI-проверки нужен Playwright MCP

### Директор — единый контекст с МДЛП
30. **НЕ использовать mock-сотрудников** (`EMPLOYEES` из `src/data/employees.ts`, `wmMockUsers` из `src/data/wmRussiaData.ts`) в директорских вкладках. Все сотрудники директора должны грузиться из `/api/admin/employees` — там 107 реальных записей из `сотрудники.xlsx` (PFO Sonin, PFO Orudjov, PFO Nechaeva, PFO Samadova и т.д.). Никаких «Смирнов Д.», «Петров А.», «Сидоров В.» с фейковыми телефонами.
31. **НЕ хардкодить планы** (`PRODUCTS.quota2025`, `BUDGET_PFO_2025.total`) в калькуляторе бюджета и графиках. План директор видит из таблицы `regional_plans` (заполняется РМ). Если планов от РМ нет — показывать «План не задан», а не фейковую цифру.
32. **НЕ ломать переключение МДЛП ↔ Панель директора** — кнопка «Вернуться в анализатор МДЛП» должна корректно переключать `appMode='wm-russia' → 'mdlp'` без белого экрана. Если в MDLP-режиме рендерится Recharts-компонент — данные должны быть валидны (числа где число, строки где строка), иначе `T.startsWith` или подобный crash сломает весь UI.
33. **Все 6 вкладок директора** (Дашборд, Калькулятор, По препаратам, По территориям, Сотрудники, Отчёты) должны реактивно реагировать на глобальные фильтры (месяцы) и переключатель Рубли/Упаковки. Если вкладка использует свой локальный стейт периода — он должен пересекаться с глобальным фильтром, а не игнорировать его.
34. **Контекст «директор работает с МДЛП-данными»** — это единый домен. После загрузки файла МДЛП через `/api/files/upload` (директор или admin) ВСЕ виджеты во ВСЕХ 6 вкладках директора пересчитываются автоматически через `SharedDataProvider` (mdlpData → SALES_DATA → useMemo deps). Никаких отдельных fetch к старым endpoints (`/api/wm-russia/*`, mock-данные).

## 🔧 Конвенции кодирования

### TypeScript
- `interface` для объектов, `type` для union/intersection
- Optional поля через `?`, не через `| undefined`
- Не `as any` — лучше `as unknown as X` или нормальный тип
- Reducer-pattern: каждый action явный, без spread `...action`

### React
- Хуки только на верхнем уровне (no conditionals)
- `useEffect` deps указывать честно, не игнорировать ESLint
- Cleanup в useEffect для `setInterval`, `setTimeout`, listeners, observers
- `useCallback` только когда передаётся в memoized child или dep useEffect
- Не использовать `useMemo` для скаляров — нужно только для объектов/массивов

### Стили
- Tailwind preferred, классы группировать: layout → spacing → typography → color → state
- shadcn/ui компоненты — не редактировать в `components/ui/`, только использовать
- Глобальные стили — `styles/globals.css`, не править в node_modules

### Файлы
- `kebab-case` для файлов: `director-dashboard.tsx`
- `PascalCase` для компонентов внутри: `export function DirectorDashboard()`
- `camelCase` для функций/переменных
- `SCREAMING_SNAKE_CASE` для констант

## 🚨 Что делать при инциденте

### Сайт не открывается / 502
1. `curl -s http://85.193.86.69/api/health` — connected?
2. `ssh root@85.193.86.69 'pm2 status'` — analizator online?
3. Если offline — `pm2 restart analizator && pm2 logs analizator --lines 30`

### Логин даёт «Ошибка сервера»
1. `pm2 logs | grep 'permission denied'` — GRANT'ы слетели?
2. Если да — `ssh root@85.193.86.69 '/root/restore-grants.sh'`
3. Если password authentication failed — пароль БД сменился, см. `memory/ops_timeweb_grants.md`

### Белый экран в дашборде
1. Открыть DevTools → Console → есть красные ошибки?
2. Если есть `Cannot read properties of undefined` — компонент крашится, найти в стектрейсе
3. Если консоль чистая — компонент возвращает `null`. Проверить `if (!currentUser) return null` (AppLayout?)

### Данные пустые после загрузки
1. `pm2 logs | grep 'Upload OK'` — загрузка завершилась?
2. `SELECT count(*) FROM world_medicine.raw_sales_rows WHERE user_id=X` — данные в БД?
3. Если данные есть но UI пустой — проверить что `SharedDataProvider.reloadFromServer()` вызывается (см. memory/MEMORY.md)
